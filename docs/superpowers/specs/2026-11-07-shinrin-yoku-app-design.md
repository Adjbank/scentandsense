# Shinrin-Yoku @ ไร่เชิญตะวัน — Design Spec

วันที่: 2026-11-07
สถานะ: ร่างแรก (สร้างในเซสชันอัตโนมัติ — ไม่ได้ผ่านการอนุมัติจาก CEO ก่อนเริ่มสร้าง ดูหัวข้อ "สมมติฐาน")

## 1. เป้าหมาย

แอปพลิเคชันเว็บแบบ mobile-first สำหรับผู้ที่ต้องการบำบัดกายและใจด้วยการ
"อาบป่า" (Shinrin-Yoku / 森林浴) ที่ศูนย์วิปัสสนาสากลไร่เชิญตะวัน จ.เชียงราย

ความสามารถหลักที่ CEO ระบุ:

1. ถ่ายรูปต้นไม้ → ระบุสายพันธุ์พืช
2. แสดงประวัติ/ความเป็นมา และ **เอกลักษณ์ด้านกลิ่น** ของพืชชนิดนั้น
3. สื่อสารเอกลักษณ์กลิ่นพืชพรรณไทยให้ผู้ปฏิบัติธรรมทั่วโลก → เนื้อหาสองภาษา (ไทย/อังกฤษ)

ผู้ใช้: ผู้ปฏิบัติธรรมชาวไทยและชาวต่างชาติที่เดินป่าในไร่เชิญตะวันด้วยโทรศัพท์มือถือ
ตัวชี้วัดความสำเร็จของรุ่นแรก: ถ่ายรูป → ได้ผลภายใน ~15 วินาที พร้อมชื่อไทย/อังกฤษ/วิทยาศาสตร์
ประวัติ และโปรไฟล์กลิ่นที่มีตัวเลขและแหล่งอ้างอิง

## 2. สมมติฐานที่ใช้ (ยังไม่ได้ยืนยันกับ CEO)

| หัวข้อ | สมมติฐาน | เหตุผล |
|---|---|---|
| แพลตฟอร์ม | Web app (Next.js) ติดตั้งเป็น PWA บนมือถือได้ | ไม่ต้องผ่าน App Store, ใช้กล้องผ่าน `<input capture>` ได้, ขึ้น Vercel ได้ทันที |
| ตัวระบุพืช | Claude vision (`claude-opus-5-5`) + ฐานข้อมูลพืชในแอป | ไม่ต้องเทรนโมเดลเอง, ให้คำอธิบายเป็นภาษาไทยได้ทันที, มี structured output |
| ฐานข้อมูลพืช | ไฟล์ TypeScript ในโค้ด 67 ชนิดตามป้ายชื่อ "สมุนไพรในสวนลำไย" (CEO ส่งรายชื่อให้ 2026-11-07) เรียงตามหมายเลขป้าย | รายการจริงของไร่; ชื่อวิทยาศาสตร์ 7 รายการติดธงให้ยืนยันจากต้นจริง |
| ภาษา | UI ไทยเป็นหลัก, สลับอังกฤษได้ | ตรงเป้าหมาย "ผู้ปฏิบัติธรรมทั่วโลก" |
| บัญชีผู้ใช้/ฐานข้อมูล | ไม่มีในรุ่นแรก | YAGNI; ประวัติการสแกนเก็บใน localStorage ของเครื่อง |

## 3. ทางเลือกที่พิจารณา

1. **(เลือก) Next.js + Claude vision + KB ในแอป** — เร็วที่สุด, คุณภาพคำอธิบายสูง, ค่าใช้จ่ายต่อภาพต่ำ (ภาพ ~1,500 token + prompt)
2. React Native + Pl@ntNet API — ต้องทำ 2 โค้ดเบส, Pl@ntNet ไม่รู้จักบริบทไร่เชิญตะวันและไม่ให้ข้อมูลกลิ่น
3. Flutter + โมเดล on-device (TFLite) — ต้องเก็บชุดข้อมูลภาพเอง หลายเดือน

## 4. สถาปัตยกรรม

```
Browser (PWA)                      Next.js (Vercel)                   Anthropic API
┌────────────────┐  POST /api/identify  ┌──────────────────┐  messages.parse  ┌────────────┐
│ /identify      │ ───────────────────▶ │ route.ts          │ ───────────────▶ │ claude-    │
│  camera/upload │   {image b64}        │  - validate       │  image + KB list │ opus-5-5   │
│  resize ≤1280px│ ◀─────────────────── │  - call Claude    │ ◀─────────────── │ structured │
│  result card   │   IdentifyResult     │  - merge with KB  │  candidates JSON │ output     │
└────────────────┘                      └──────────────────┘                   └────────────┘
         │ reads                                 │ reads
         ▼                                       ▼
   src/data/plants.ts  (ฐานข้อมูลพืช + โปรไฟล์กลิ่น + แหล่งอ้างอิง)
```

### หน้าจอ
- `/` หน้าแรก: แนะนำ Shinrin-Yoku, ไร่เชิญตะวัน, ปุ่ม "ถ่ายรูปต้นไม้"
- `/identify` ถ่ายรูป/อัปโหลด → ผลลัพธ์ (ชื่อ, ความมั่นใจ, ประวัติ, กลิ่น, สารหอมหลัก, แหล่งอ้างอิง)
- `/plants` แคตตาล็อกพืชหอมในไร่, ค้นหา/กรองตามกลุ่มกลิ่น
- `/plants/[slug]` รายละเอียดพืช
- `/walk` เส้นทางอาบป่าแบบมีไกด์: 5 สถานี × ประสาทสัมผัส + ตัวจับเวลาหายใจ

### โมดูล
| โมดูล | หน้าที่ | พึ่งพา |
|---|---|---|
| `src/data/plants/part1–4.ts` + `src/data/plants.ts` | ข้อมูลพืช 67 ชนิด (type `Plant` มี `signNo`), `PLOT` metadata | — |
| `src/lib/identify/schema.ts` | zod schema ของผลลัพธ์จาก Claude | zod |
| `src/lib/identify/merge.ts` | รวม candidates กับ KB → `IdentifyResult` (pure, ทดสอบได้) | plants, schema |
| `src/lib/identify/claude.ts` | เรียก Claude (`client.beta.messages.parse`, fallbacks "default") | SDK |
| `src/app/api/identify/route.ts` | ตรวจ input, เรียก claude.ts, คืน JSON/ข้อผิดพลาด | ทั้งหมด |
| `src/lib/i18n.ts` | พจนานุกรม UI ไทย/อังกฤษ + hook | — |
| `src/components/*` | ResultCard, PlantCard, CameraCapture, LangToggle, Nav | — |

### การไหลของข้อมูล `/api/identify`
1. รับ `{ image: base64, mediaType }` (≤ 5 MB หลัง resize ฝั่ง client)
2. ไม่มี `ANTHROPIC_API_KEY` → 503 `{code: "NO_API_KEY"}`
3. system prompt (cache_control) = บทบาทนักพฤกษศาสตร์ + รายการพืชใน KB (slug, เลขป้าย, ชื่อวิทย์, ชื่อไทย) + บริบทว่าเป็นกล้าไม้อายุน้อยในแปลงลำไย
4. Claude คืน `{ isPlant, candidates[≤3]{scientificName, thaiName, englishName, family, confidence 0–1, matchedSlug|null, reasoning}, observedFeatures[] }`
5. `merge()` : ถ้า `matchedSlug` อยู่ใน KB → แนบข้อมูล KB; ถ้าไม่ → ใช้ข้อมูลที่โมเดลสรุป (scentSummary, history) และติดธง `inKnowledgeBase: false`
6. `stop_reason === "refusal"` → 422 `{code: "REFUSED"}`; parse ล้มเหลว → 502

### การจัดการข้อผิดพลาด
- ไม่ใช่พืช → `isPlant=false` แสดงข้อความให้ถ่ายใหม่
- ไม่มีคีย์ → แสดงคำแนะนำตั้งค่า + ลิงก์ไปแคตตาล็อก
- เครือข่ายล้มเหลว → ข้อความและปุ่มลองใหม่

### การทดสอบ
- vitest: ตรวจ KB (slug ไม่ซ้ำ, ฟิลด์ครบ, ผลรวม % สารหอมไม่เกิน 100, ทุกชนิดมี ≥1 แหล่งอ้างอิง)
- vitest: `merge()` ทั้งกรณีอยู่/ไม่อยู่ใน KB, ไม่ใช่พืช
- vitest: route ไม่มีคีย์ → 503; body ไม่ถูกต้อง → 400
- `next build` + Playwright screenshot หน้าหลัก
